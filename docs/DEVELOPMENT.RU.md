# Разработка и эксплуатация

[English version](DEVELOPMENT.md) · [Обзор проекта](../README.RU.md)

## Среда сборки

В проекте используются Gradle 8.11.1, Android Gradle Plugin 8.7.3, Kotlin 2.0.21 и KSP 2.0.21-1.0.28. Целевая версия JVM для Java и Kotlin — 17. Для сборки рекомендуется JDK 17; в Android Studio он выбирается как Gradle JDK.

В Android SDK нужны Platform 35 и принятые лицензии. Путь к SDK задаётся переменной `ANDROID_HOME` либо параметром `sdk.dir` в локальном файле `local.properties`. Приложение нацелено на API 35 и работает на Android 8.0 (API 26) или новее.

Команды ниже выполняются из корня репозитория. В Windows вместо `./gradlew` используется `.\gradlew.bat`. При первом запуске wrapper скачивает Gradle; режим `--offline` работает после сохранения нужного дистрибутива и зависимостей в кэше.

```bash
./gradlew :app:assembleDebug
./gradlew :app:assembleRelease
```

| Вариант | APK | Настройки |
|---|---|---|
| Debug | `app/build/outputs/apk/debug/app-debug.apk` | С отладкой, для разработки |
| Release | `app/build/outputs/apk/release/app-release.apk` | Без отладки, с оптимизацией R8 и удалением неиспользуемых ресурсов |

## Подпись и установка APK

Оба варианта используют debug-подпись Android. Сборки с одним debug-keystore могут обновлять друг друга. Новый keystore содержит другой ключ подписи — в том числе на чистом runner CI. Его APK не установится как обновление поверх приложения с другим ключом.

Для совместимой сборки на телефоне с включённой USB-отладкой доступна команда:

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

При ручной установке APK копируется на телефон и открывается через файловый менеджер. Android запрашивает разрешение на установку из этого источника. USB-отладка для этого не нужна.

GitHub Actions сохраняет debug- и release-APK в артефактах запуска вместе с отчётами тестов и lint. Артефакт скачивается со страницы завершённого запуска. Эти сборки сохраняют debug-подпись. Для отдельно поддерживаемого распространения нужны постоянный закрытый ключ подписи и растущие коды версий.

## Первый запуск и разрешения

1. Принтер сопрягается в настройках Bluetooth телефона. NotiPrint выбирает устройства из списка уже сопряжённых.
2. После выдачи разрешения Bluetooth/«Устройства поблизости» принтер выбирается кнопкой **«Выбрать принтер»**.
3. Кнопка **«Тестовая печать»** отправляет пример чека с кириллицей и диагностический шаблон покрытия.
4. Кнопка **«Разрешить доступ»** открывает доступ к уведомлениям. Для приёма событий также выдаются запрошенные разрешения СМС, контактов, журнала вызовов и уведомлений приложения.
5. В настройках телефона разрешаются фоновая работа и автозапуск. Кнопка **«Настроить автозапуск»** открывает соответствующие настройки, если устройство их предоставляет.

| Доступ | Для чего используется |
|---|---|
| Bluetooth / «Устройства поблизости» | Соединение с выбранным сопряжённым принтером |
| Доступ к уведомлениям | Пропущенные звонки и календарь; резервный приём уведомлений СМС |
| Приём СМС | Прямой приём СМС независимо от вида уведомлений СМС-приложения |
| Контакты | Имена отправителей, фильтр неизвестных номеров и выбор контакта для чёрного списка |
| Журнал вызовов | Имя и номер последнего пропущенного звонка |
| Уведомления приложения | Постоянное уведомление foreground-сервиса |

Интерфейс и заголовки типов событий на чеках сейчас на русском языке. Все типы событий включены по умолчанию. Ночной интервал — 22:00–08:00; в приложении он меняется или отключается. Одинаковые начало и конец также отключают интервал.

Локальный чёрный список действует на СМС и пропущенные звонки. Он принимает номер телефона или буквенную метку отправителя; из выбранного контакта можно добавить все номера. Фильтр СМС с незнакомых номеров применяется к числовым отправителям. Буквенные метки проходят этот фильтр, если не внесены в чёрный список.

## Автоматические проверки

```bash
./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug :app:assembleRelease
```

21 JVM-тест проверяет классификацию уведомлений, расчёт ожидания принтера, ночные интервалы, задержки повторов и обработку очереди с управляемыми сеансами принтера. Сценарии очереди включают ошибку отправки с последующим восстановлением, прерванную работу, одновременные обработчики и продолжение после партии из 50 заданий.

Локальная проверка выполнена с OpenJDK 21.0.12.1 и Gradle 8.11.1: 21 JVM-тест прошёл, lint сообщил о нуле ошибок и 19 предупреждениях, debug-, оптимизированный release- и инструментальный APK собраны. В CI используется JDK 17. Предупреждения lint в основном касаются обновления зависимостей и существующих проверок версий SDK.

Для инструментальных тестов Room нужен эмулятор Android или телефон:

```bash
adb devices
./gradlew :app:connectedDebugAndroidTest
```

Пять тестов используют настоящие Room и WorkManager с управляемым сеансом принтера. Три сценария повторно открывают файловую базу и проверяют сохранённое событие, прерванную строку и неудачную отправку. Два сценария планирования проверяют очередь из 120 событий с тремя обработчиками и выключенный принтер с последующим отложенным повтором и сбросом задержки. Bluetooth-принтер не требуется. GitHub Actions запускает эти тесты на API 35 отдельно от модульных проверок и сборки.

Отчёты находятся в `app/build/reports/tests/`, `app/build/reports/androidTests/` и `app/build/reports/lint-results-debug.html`. XML-результаты модульных тестов — в `app/build/test-results/`, инструментальных — в `app/build/outputs/androidTest-results/`.

## Проверка на устройстве

Для дневной проверки ночной интервал отключается либо задаётся за пределами текущего времени. История и счётчик ожидания в приложении показывают состояние очереди. Логи обработчиков и слушателя доступны командой:

```bash
adb logcat -s NotiPrintWorker NotiPrintListener
```

| Сценарий | Ожидаемое поведение |
|---|---|
| Входящая СМС, пропущенный звонок, событие календаря | Подходящее событие появляется в истории и печатается читаемым чеком |
| Принтер выключен, затем включён | Событие остаётся в ожидании; повторная попытка или восстановление Bluetooth запускают очередь |
| Процесс приложения прерван во время печати | Следующий запуск восстанавливает незавершённую строку; уже переданный чек может напечататься повторно |
| Тестовая печать запрошена во время работы очереди | Принтер выполняет операции по одной, растровые потоки не смешиваются |
| Ночной интервал проходит через полночь | События остаются в очереди внутри интервала и печатаются после его окончания |
| Отправитель в чёрном списке | Его СМС или пропущенный звонок с определённым номером не добавляются в очередь |
| Включён фильтр СМС с незнакомых номеров | Неизвестные числовые отправители отбрасываются, буквенные метки вне чёрного списка принимаются |
| Перезагрузка телефона | При сохранённых разрешениях и фоновой работе сервис запрашивает подключение слушателя и обработку очереди |

Диагностический тест обращается к принтеру напрямую под общей блокировкой. Он не сохраняется в очереди событий и доступен во время ночного интервала.

## Диагностика принтера

Для передачи нужны Bluetooth Classic SPP, бумага 58 мм, область печати шириной 384 точки и поддержка растровых команд ESC/POS `GS v 0`. MUNBYN IMP006 — модель, на особенности которой опираются решения о непрерывной передаче растра и отступах бумаги в коде.

Если задание остаётся в ожидании, проверяются выбранный принтер, разрешение Bluetooth, питание, дальность связи и ночной интервал. При ошибке задания её текст виден в истории событий. Фоновая работа и доступ к уведомлениям настраиваются на телефоне отдельно.

При бледной или неравномерной печати диагностическая страница помогает сравнить текст и плотные чёрные области. На результат влияют заряд аккумулятора и термочувствительность бумаги. Для IMP006 указана термобумага шириной 58 мм и толщиной 0,06–0,08 мм.

Обычные уведомления используют растровые полосы по 128 строк, ручная диагностика — по 256. В обоих случаях полосы передаются без намеренных пауз. Завершение передачи и расчётное ожидание принтера описаны в [архитектуре](ARCHITECTURE.RU.md#изображение-и-передача-escpos).
